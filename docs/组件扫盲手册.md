## 总览：这些组件分成四大类

这些名词都是**别人做好的现成工具**，你不用自己实现，只要会调用就行。按「解决什么问题」分成四类：

| 分类 | 解决的问题 | 包含组件 |
|---|---|---|
| **① 让你的代码能被调用** | 你写的函数只在本地跑，别人碰不到 | FastAPI、Uvicorn、Pydantic |
| **② 把数据存起来** | 数据存下来、查得到、找得准 | SQLite、SQL、向量库（Chroma） |
| **③ 处理文字和 AI** | 让机器理解文字、回答问题 | Embedding、LLM、Prompt、RAG、Token |
| **④ 打包与自动化** | 换台机器也能跑 + 提交代码后自动干活 | Docker、docker-compose、CI/CD、GitHub Actions、Webhook |

一句话记忆：

- 想让**别人访问**你的函数 → 第一组
- 想让**数据留下来** → 第二组
- 想让**机器懂文字** → 第三组
- 想让**程序到处能跑、自动干活** → 第四组

## 第一组：让你的代码能被调用

你写的函数默认只能在你自己电脑上跑，别人碰不到。这一组解决这个问题。

### FastAPI

**大白话**：给 Python 函数挂一个「网址」，别人访问网址就等于调用了你的函数。

```python
@app.get("/api/health")        # 就是这个装饰器，把函数挂到网址上
def health():
    return {"status": "ok"}    # 访问 http://127.0.0.1:8000/api/health 就执行它
```

它附赠一个大礼包：**自动生成 `/docs` 网页**，可以在页面上点按钮测试每个接口 —— 你之前做 CRUD 用的那个页面就是它送的。

**项目里**：`src/api.py`

---

### Uvicorn

**大白话**：让服务真正跑起来的引擎。

**类比**：FastAPI 是菜谱，Uvicorn 是厨房和服务员。你执行 `uvicorn src.api:app` 就是「开张营业」，它负责守着 8000 端口、接待每一个请求。

**项目里**：`python -m src.main serve` 内部就是调它。

---

### Pydantic

**大白话**：自动检查传进来的数据格式对不对。

**类比**：就是你学过的类型提示（type hints），但它在**运行时真的会检查并报错**。

```python
class DiagnosisUpdate(BaseModel):
    status: str | None = None     # 声明：status 要么是字符串，要么不传
```

你传 `status="abc"`，它返回 400 错误告诉你格式不对，而不是让程序莫名其妙崩掉。

**项目里**：`src/api.py` 顶部的请求模型。

## 第二组：把数据存起来

### SQLite

**大白话**：Python **自带**的数据库，整个数据库就是一个文件（`data/doctor.db`）。

**类比**：类似你用 `json` 模块读写文件，但它支持查询、筛选、排序，而且程序崩了也不容易把文件写坏。

```python
import sqlite3

conn = sqlite3.connect("data/doctor.db")   # 连上（文件不存在就创建）
conn.execute("INSERT INTO diagnoses (service) VALUES ('redis')")
```

**项目里**：`src/db.py`

---

### SQL 与 CRUD

**大白话**：操作数据库的语言，只有四个动作 —— 这就是 CRUD。

| SQL 动作 | 对应 Python 列表操作 | 含义 |
|---|---|---|
| `INSERT` | `list.append(x)` | 增 |
| `SELECT` | 遍历 / 筛选列表 | 查 |
| `UPDATE` | `list[0] = x` | 改 |
| `DELETE` | `list.remove(x)` | 删 |

**项目里**：`src/db.py` 里的 5 个函数，一个动作一个函数，结构非常清楚。

### 向量库 / Chroma / 余弦相似度

这是**最难懂但最关键**的部分，我拆开讲。

#### 第一步：理解「向量」

把一句话变成一串数字，用数字代表它的「意思」。

```python
embed("连接失败")   # → [0.12, -0.85, 0.33, ...]   约 1000 个数字
embed("无法连接")   # → [0.15, -0.81, 0.35, ...]   很接近！
embed("磁盘满了")   # → [-0.72, 0.11, 0.08, ...]   差很远
```

#### 第二步：理解「余弦相似度」

判断两串数字有多像的公式，结果 0~1，越接近 1 越像。

```python
similarity(embed("连接失败"), embed("无法连接"))   # 0.96  ← 很像
similarity(embed("连接失败"), embed("磁盘满了"))   # 0.12  ← 不像
```

#### 第三步：理解「向量库」

向量库 = 专门存这些数字、并能快速找出「哪串数字跟我最像」的数据库。

**类比**：

- 普通数据库是**精确查找**：`WHERE 名字 = '张三'`
- 向量库是**模糊找相似**：找出意思最接近的 3 条

Chroma 是向量库的一种。**而我在项目里还写了个纯 Python 版本**：把数字存进列表，用 for 循环一个个算相似度 —— 就是所谓的「内存向量库」，装不上 Chroma 时自动用它。

**项目里**：`src/rag.py`

## 第三组：处理文字和 AI

### Embedding（向量化）

**大白话**：就是上面「把文字变成数字」这个动作的正式名称。

两种做法：

1. **调 API**（效果好，要花钱）：把文字发给服务商，返回数字数组
2. **本地算**（免费，效果一般）：我项目里用的是「统计字词出现次数」，把词频当数字

**项目里**：`src/rag.py` 的 `SimpleEmbedder`（本地）和 `APIEmbedder`（调 API）。

---

### 大模型 / LLM

**大白话**：就是 ChatGPT、DeepSeek 这类能对话的 AI。LLM = Large Language Model。

**类比**：像一个远程函数，你发文字过去，它返回文字回来。

```python
resp = requests.post(
    "https://api.deepseek.com/chat/completions",
    json={"messages": [{"role": "user", "content": "分析这段日志"}]}
)
回答 = resp.json()["choices"][0]["message"]["content"]
```

**注意**：要注册拿 API Key，按用量付费（很便宜，诊断一次不到一分钱）。

**项目里**：`src/llm.py` 的 `call_llm()`

---

### Prompt（提示词）

**大白话**：你发给大模型的那段文字。写得具体，它答得就好；写得含糊，它就瞎答。

**项目里**：`src/llm.py` 里的 `USER_PROMPT_TEMPLATE`，就是一段带占位符的模板文字，把日志和参考资料填进去。

---

### RAG

全称 **Retrieval-Augmented Generation**（检索增强生成）。

**大白话**：**先查资料，再让 AI 回答**。

**类比**：闭卷考试 vs 开卷考试。不查资料直接问，AI 会编；先塞给它几篇相关资料，它答得准得多，而且能告诉你「依据是哪一篇」。

**项目里**：`src/rag.py` 负责查资料，`src/llm.py` 负责把资料塞进 Prompt。

---

### Token

**大白话**：大模型计费和长度限制的单位，1 个汉字大约 1~2 个 token。

**为什么要知道**：日志可能几千行，全发过去又贵又超限。所以项目里只截取异常前后几行（`extract_context()` 干的事）。

## 第四组：打包与自动化

### Docker / 容器

**要解决的问题**：你的程序在你电脑上跑得好好的，换台服务器就报错（Python 版本不对、缺库、缺系统依赖）。

**Docker 的解法**：把程序 + Python 版本 + 所有依赖 + 系统环境，整体打包成一个「盒子」，到哪台机器都能一模一样地跑。

三个词要分清：

| 名词 | 类比 | 说明 |
|---|---|---|
| **镜像** image | 安装包 | 只读的模板 |
| **容器** container | 装好的程序 | 用镜像跑起来的实例，可启动可停止 |
| **Dockerfile** | 打包说明书 | 描述「怎么打包」的文本文件 |

**项目里**：`Dockerfile`（打包主程序）、`demo_app/Dockerfile`（打包被监控的示例应用）

---

### docker-compose

**大白话**：一个文件描述「要启动哪几个容器、端口怎么映射、谁依赖谁」，一条命令全起来。

```bash
docker compose up -d      # 一条命令起 Nginx + Flask + MySQL
```

**项目里**：`docker-compose.yml`

---

### CI/CD

- **CI**（持续集成）：每次提交代码，自动跑测试，防止改坏
- **CD**（持续交付）：测试通过后自动打包、部署

**大白话**：你只管提交代码，后面的活机器人干。

**类比**：像一个自动化脚本，只不过由 GitHub 的服务器在你 push 代码时自动触发。

---

### GitHub Actions

**大白话**：GitHub 提供的免费 CI/CD 服务。你在仓库里放一个 YAML 文件描述「要做什么」，它就照做。

**YAML 类比**：像配置文件，靠**缩进**表示层级（和 Python 一样），比 JSON 好读。

**项目里**：

- `.github/workflows/ci.yml`（跑测试 + 构建镜像）
- `.github/workflows/ai-diagnose.yml`（流水线失败时 AI 诊断）

---

### Webhook

**大白话**：一个网址。当某件事发生时，系统主动往这个网址发消息通知你。

**项目里的延伸用法**：钉钉 / 飞书机器人的地址就是一个 webhook，你往它 POST 一条消息，群里就弹出通知。

---

### Traceback

**大白话**：Python 报错时打印的那一大段堆栈信息。你其实早就见过，只是不知道它的名字 —— 比如 `KeyError` 下面那一串 `File "...", line 42, in xxx`。

## 附录 A：学习优先级排序

不用一次性全懂。按「必须懂 / 可以先放着」排个序：

| 优先级 | 组件 | 理由 |
|---|---|---|
| 🔴 必须先懂 | FastAPI + Pydantic | 项目的接口全靠它，`/docs` 里能直接练手 |
| 🔴 必须先懂 | SQLite + SQL 四个动作 | CRUD 是运维开发的基本功 |
| 🟡 其次 | Embedding + 向量 + 余弦相似度 | 理解 RAG 的前提，代码只有十几行，可以自己读 |
| 🟡 其次 | Docker 三个概念 | JD 的硬要求，先会 `docker run` / `docker logs` |
| 🟢 可以先放着 | Chroma | 知道「有这东西、装不上有替代品」就够了 |
| 🟢 可以先放着 | GitHub Actions / YAML | 照着现成的改参数就行，不用从零写 |
| 🟢 可以先放着 | Webhook | 等要做告警通知时再学，半小时的事 |

## 附录 C：给新手最重要的一句话

> 这些组件都只是「工具」，你写的核心逻辑永远是**普通 Python 函数**。

比如 `src/detector.py` 里的 `detect()`，本质就是：

```
读字符串  →  用正则找关键字  →  返回一个对象
```

这个你完全看得懂。框架只是帮你把这些函数**接到网络上、接到数据库上**而已。

先看 `detector.py`，再看 `pipeline.py`，你会发现整个项目最核心的 60 行代码，全是你能读懂的东西。
