# 中间件日志源搭建指南（nginx / Tomcat / MySQL）

> **目的**：让 ai-log-doctor 采集**真实中间件产生的日志**，而不是手写样本。
>
> **核心原则**：不往日志文件里写一个字符。所有报错都通过**发起真实请求、触发真实故障**产生，
> 由服务自己记录。这样日志的格式、字段、异常栈都是真的，能被真实排障逻辑处理。

## 二、环境约束与应对（这台机器很特殊）

| 约束 | 影响 | 应对 |
|---|---|---|
| **没有 gcc** | nginx 无法源码编译 | 改走 **RPM 解压**：`rpm2cpio nginx.rpm \| cpio -idm` |
| **CentOS 7 只自带 PCRE1** | nginx 1.23+ 需要 `libpcre2-8.so.0` | 额外解压 `pcre2-10.23-2.el7` 包补上库 |
| **nginx 编译期默认 temp 路径在 `/var/cache/nginx`** | 启动时 `mkdir failed` 直接失败 | 配置里显式指定全部 5 个 temp 路径 + 建好 `/var/log/nginx` |
| **磁盘只剩 2.9G** | 装不下 MySQL（解压后 2.5G） | MySQL 跳过，复用系统现有实例 |
| **外网要走国内镜像** | GitHub / 官方源慢或 404 | 全部走清华 / 阿里云 / 华为云镜像 |

## 三、安装 nginx（RPM 解压，不走 yum）

```bash
# 1. 下载（nginx.org 官方 el7 RPM + CentOS vault 的 pcre2）
#    nginx-1.24.0-1.el7.ngx.x86_64.rpm
#    pcre2-10.23-2.el7.x86_64.rpm

# 2. 解压 nginx 到 /nginx
cd /nginx && rpm2cpio /pkg/nginx-1.24.0-1.el7.ngx.x86_64.rpm | cpio -idm --quiet

# 3. 补 PCRE2 库（关键：CentOS 7 没有）
mkdir -p /nginx/lib && cd /nginx/lib
rpm2cpio /pkg/pcre2-10.23-2.el7.x86_64.rpm | cpio -idm --quiet
find /nginx/lib -name 'libpcre2-8.so*' -exec cp -a {} /nginx/lib/ \;
rm -rf /nginx/lib/usr
echo "/nginx/lib" > /etc/ld.so.conf.d/nginx-local.conf && ldconfig

# 4. 启动
/nginx/usr/sbin/nginx -t -c /nginx/conf/nginx.conf && \
/nginx/usr/sbin/nginx    -c /nginx/conf/nginx.conf
```

完整脚本：`scripts/setup-nginx.sh`

### 一个关键的配置细节

`log_format` 里**必须保留 `$remote_user`**，否则字段位会错：

```
# ❌ 错误写法：[$time_local] 里有空格，导致状态码不在第 9 列
'$remote_addr - [$time_local] "$request" $status ...'

# ✅ 正确写法：与标准 combined 格式字段位对齐，$9 才是状态码
'$remote_addr - $remote_user [$time_local] "$request" $status ...'
```

**为什么重要**：后续用 `awk '$9 ~ /^[45][0-9][0-9]$/'` 过滤 4xx/5xx 时，字段错位会导致一个错误都筛不出来。

## 四、安装 Tomcat + JDK（tarball 解压）

```bash
# 1. 解压
mkdir -p /java && tar -xzf /pkg/jdk-8u202-linux-x64.tar.gz -C /java --strip-components=1
mkdir -p /tomcat && tar -xzf /pkg/apache-tomcat-9.0.122.tar.gz -C /tomcat --strip-components=1

# 2. 写 /tomcat/bin/setenv.sh —— 堆故意设小，让 OOM 能被真实触发
export JAVA_HOME=/java
export CATALINA_HOME=/tomcat
export JAVA_OPTS="-Xms64m -Xmx128m"

# 3. 启动
/tomcat/bin/startup.sh
```

完整脚本：`scripts/setup-tomcat.sh`

### 为什么用 JSP 制造异常，而不是写 Java 类？

**JSP 由 Tomcat 在运行时自己编译**，不需要我们提前 `javac`、也不用手写 `web.xml`。
但产生的是**真正的 Java 异常栈**——和我们写一个 servlet 抛异常完全等价。

部署的测试应用 `/tomcat/webapps/ops-app/`：

| 页面 | 触发什么真实异常 |
|---|---|
| `npe.jsp` | `java.lang.NullPointerException` |
| `throw.jsp` | `java.lang.IllegalStateException`（带业务消息） |
| `conn.jsp` | `java.net.ConnectException`（连未监听端口） |
| `sql.jsp` | `java.lang.ClassNotFoundException`（缺少 JDBC 驱动） |
| `oom.jsp` | `java.lang.OutOfMemoryError: Java heap space` |
| `slow.jsp` | 睡 15 秒 → 用来触发 nginx 的真实 504 |

> ⚠️ **注意堆转储**：`-XX:+HeapDumpOnOutOfMemoryError` 会生成 100MB+ 的 `.hprof` 文件。
> 在磁盘紧张时建议关掉，否则几次 OOM 就把磁盘占满了（实测一次 113MB）。

## 五、生成真实错误（`scripts/gen-real-errors.sh`）

### nginx 产生的真实错误

| 操作 | 得到什么 | 日志里的原文 |
|---|---|---|
| 访问 `/api/`（配了个不存在的上游 9999） | **502** | `connect() failed (111: Connection refused) while connecting to upstream` |
| 访问 `/files/不存在.pdf` | **404** | `open() "/nginx/html/files/xxx.pdf" failed (2: No such file or directory)` |
| 访问 `/secret/`（无 index 的目录） | **403** | `directory index of "/nginx/html/secret/" is forbidden` |
| POST 2MB（上限 1m） | **413** | `client intended to send too large body: 2097152 bytes` |
| 经 nginx 访问 `slow.jsp`（15s > 5s 超时） | **504** | `upstream timed out (110: Connection timed out) while reading response header` |

### Tomcat 产生的真实错误

访问 `ops-app` 下那几个 JSP，得到 6 类真实 JVM 异常栈，同时访问日志里留下真实的 `500` / `404`。

### MySQL 产生的真实错误

```bash
# 用错误口令登录 → 错误日志里出现真实的 Access denied
mysql -h127.0.0.1 -u baduser -p'wrong_password' -e "SELECT 1"
# → [Note] Access denied for user 'baduser'@'localhost' (using password: YES)
```

**另外**：这台机器原本的 `/var/log/mysqld.log` 里已经有 **9936 条真实 ERROR**，
包含一次真实生产事故——MySQL 因为 **3306 端口被占用**反复启动失败：

```
[ERROR] Can't start server: Bind on TCP/IP port: Address already in use
[ERROR] Do you already have another mysqld server running on port: 3306 ?
[ERROR] Aborting
```

**这是真实历史，不是我们造的 —— 比任何模拟数据都有说服力。**

## 六、采集与运行

```bash
# 1. 采集（按中间件 + 错误类型拆成独立文件）
bash /opt/ai-log-doctor/scripts/collect-all-logs.sh 800

# 2. 分析
cd /opt/ai-log-doctor
venv/bin/python -m src.main ingest --dir /opt/logs --clear
```

### 为什么按「错误类型」拆文件？

因为程序切分日志时会**取上下文**（前 2 行后 3 行）。如果把不同故障混在一个文件里，
上下文会把无关的错误卷进来，导致结论被污染 —— 这个坑在之前用真实日志时已经踩过。

所以采集脚本主动拆成：

| 文件 | 内容 |
|---|---|
| `nginx-error.log` | nginx 错误日志 |
| `nginx-access.log` | 仅 4xx/5xx 访问记录 |
| `tomcat-catalina.out` | 容器日志 |
| `tomcat-app.log` | 应用异常栈 |
| `tomcat-access.log` | 仅 4xx/5xx 访问记录 |
| `mysql-error.log` | 仅 `[ERROR]` 行 |
| `mysql-warning.log` | 仅 `[Warning]` 行 |

## 七、这次真实日志暴露的两个缺陷（都已修复）

### 缺陷 ①：纯数字关键字没有词边界 → 大量误报

**现象**：159 条记录里 138 条来自 MySQL，而且根因明显不对 ——
`[Warning] TIMESTAMP with implicit DEFAULT value is deprecated` 被判成「Nginx 502」。

**根因**：

```
2026-09-03T07:39:35.635045Z 0 [Warning] CA certificate ca.pem is self signed
                        ↑ 微秒里的 "635045" 包含 "504"
```

关键字列表里的 `502` / `503` / `504` 是**裸数字**，会被日志里任何包含这三个数字的
随机串误命中 —— 时间戳微秒、字节数、内存地址、ID 全都会撞上。

**修复**（`detector.py::_build_keyword_pattern`）：

```python
if k.isdigit():                                  # 502 / 503 / 504
    esc = r"\b" + esc + r"\b"                    # 加词边界
elif k.isalpha() and k.isupper() and len(k) <= 4:  # OOM 这类短词
    esc = r"\b" + esc + r"\b"                    # 避免 ROOM / ZOOM / BLOOM 误命中
```

**效果**：内核日志的 6 条误报消失；真实 `502` 状态码仍能正确命中。

### 缺陷 ②：同一故障重复上千次 → 面板被刷屏

**现象**：153 条记录里，**132 条是同一个故障**（3306 端口被占用）。

**关键数据（实测）**：

```
记录总数        : 153
按原文去重      : 151   ← 几乎没有重复
按归一化模板去重: 20    ← 真实只有 20 种故障
```

**为什么 MD5 去重没用**：每行都带时间戳，原文永远不一样。

**修复**（`detector.py` 新增 `fingerprint()` + `split_by_error_patterns(dedup=True)`）：

把时间戳、十六进制、纯数字替换成占位符，得到稳定的「模板」，用模板哈希判重。
重复的段落只保留一份，并在开头标注总次数。**这正是 ELK 里 fingerprint 处理器的思路。**

```
# 同类异常在本次日志中共出现 132 次（已按归一化模板聚合，以下为其中一次的完整上下文）
2026-09-03T07:35:13.201105Z 0 [ERROR] Do you already have another mysqld server running on port: 3306 ?
```

**效果**：**164 片段 / 153 条 → 29 片段 / 20 条**，正好等于实测的 20 种真实故障。

> **对原有样本零影响**：项目自带的 `samples/app-logs` 是手工构造的、每个错误都不重复，
> 去重前后都是 **22 段**，所以文档里「22 片段 / 21 条」的数字依然有效。

## 八、还没解决的两个问题（下一步）

### 1. 片段边界会切在堆栈中间

Tomcat 的异常栈很长，切分时可能从中间开始，导致片段里**看不到异常头**，
只有一堆 `at org.apache.tomcat...` 的栈帧。AI 拿到这种片段判断会不准。

**方案**：切分时向上回溯，遇到 `Exception` / `Error` 关键字所在行就停，保证异常头在片段内。

### 2. RAG 检索准确度偏低

实测相似度普遍在 **0.02 ~ 0.29**，而且出现过 `directory index is forbidden`
检索到 `bind() to 0.0.0.0:80 failed` 这种不匹配的情况。

**原因**：没有配置远程 Embedding API，走的是本地字符 bigram 词频算法，
对英文技术日志的语义表达能力弱。

**方案**：配置 `EMBED_API_KEY` 走远程 embedding；或改用更合适的本地算法
（比如按 token 切分的 TF-IDF，而不是按字符 bigram）。
